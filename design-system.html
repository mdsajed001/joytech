Token architecture

Three tiers, one direction of truth. Components never reference a raw hex value — they reference a semantic token, which resolves to a primitive ramp step. Swapping the brand palette means changing seven seed colors in tier 1; nothing in tiers 2 or 3 changes.

1 · Primitives

Generated color ramps, spacing scale, radius scale. Pure values, no meaning attached.

--primary-600: #1a4fb8
→

2 · Semantic

Primitives given a job: background, text, border, feedback role. This is what designers pick from.

--color-brand-primary
→

3 · Component

Semantic tokens applied to a specific part of a specific component.

.btn-primary { background }

Naming convention: primitives are --{ramp}-{step} (e.g. --danger-700), semantic tokens are --color-{role}-{variant} (e.g. --color-text-secondary, --color-success-bg). Never write a component style against a primitive directly — always go through a semantic token, even if today it happens to point at the same value.

Color system

Seven seed colors — primary, secondary (warm CTA accent), success, warning, danger, info, and neutral — each expand into a 12-step ramp (25 through 950). Feedback colors stay inside a semantic hue band even when randomized, so red never stops meaning "error."

Semantic tokens (current mode)

These are the tokens components actually consume. Toggle dark mode above — the mapping rule changes, not the component code.

Typography

Two families: Manrope for Latin UI text and numerals, Noto Sans Bengali for Bangla script — matched at similar optical weight so mixed-language strings (common on every screen: product names, categories, reviews) sit evenly on the same line. Bangla runs get +15% line-height; conjuncts need the extra room Latin doesn't.

Body copy stays at 14px minimum for Bangla (13px is where conjunct clusters start losing legibility on mobile screens); Latin-only captions can drop to 12px. Line length caps at 70 characters for body paragraphs.

Spacing & grid

4px base unit. Component-internal spacing uses steps 1–4 (4/8/12/16); spacing between components uses 4–6 (16/20/24); page-level rhythm uses 8+ (32/40/48/64).

Corner radius

Six steps, each tied to a real component pattern observed across the source screens — search fields sit between button and banner rounding, status pills and avatars are always fully round, bottom navigation stays sharp.

Elevation & borders

The interface is mostly flat — hairline borders carry most separation, with shadow reserved for things that float above content: sticky checkout bars, floating actions, menus, modals. Shadows stay neutral regardless of the active brand palette; elevation is physical, not brand-colored.

Motion

Motion answers an action — it never plays on load. Short durations for anything under the thumb (taps, toggles), slightly longer for content entering/leaving the screen.

Iconography

Outline style, 1.75–2px stroke at a 24px box (scales down cleanly to 16px for inline use). Filled variant reserved for the active/selected state only — bottom navigation, selected filters — never for a resting default state.

Buttons

Five intents, three sizes, and the disabled state — every button is built the same way underneath (min 44px hit target regardless of visual size), only visual size shrinks below 44px for the small variant inside dense rows.

Primary = --color-brand-primary, filled, for the one action per screen you want taken. Outline and ghost share the same primary color at lower visual weight for secondary actions. Danger uses the danger ramp's solid step with an automatically-picked white/near-black label for guaranteed contrast.

Accessibility — built for AAA

This isn't a bolt-on audit pass; contrast is enforced at the token level, so any future palette change is checked automatically by the same math used in the color section above.

Criterion
Requirement
How this system meets it
Text contrast
7:1 normal text, 4.5:1 large text (WCAG 1.4.6, AAA)
--color-text-primary and --color-text-secondary are chosen from the shade with a passing badge in the ramp above — regenerated on every palette change.
Non-text contrast
3:1 for UI components and graphical objects (1.4.11)
Borders use --border-strong at minimum; icons inherit text color, never a low-contrast tint.
Touch target size
44×44 CSS px minimum, 8px spacing between adjacent targets (2.5.5, AAA)
All buttons, nav items and steppers hold a 44px minimum tap area even when the visible chip is smaller.
Focus visibility
Clearly visible, never suppressed (2.4.7 / 2.4.11)
2.5px outline + 2px offset on every interactive element; never outline:none without a replacement.
Color independence
Never convey meaning by color alone (1.4.1)
Status badges carry a text label, alerts carry a distinct icon shape per severity.
Motion
Respect reduced-motion preference (2.3.3, AAA)
Global prefers-reduced-motion query collapses all durations.
Language of parts
Mark language changes inline (3.1.2)
Bangla text runs are wrapped in lang="bn", which also triggers the wider line-height rule.
Line length
No more than ~80 characters per line (1.4.8, AAA)
Body copy is capped at 64–70ch via max-width.

Governance

      

        
    
          
  • Only seven values are ever hand-picked: the seeds. Everything else — 84 primitive shades, ~30 semantic tokens, every component style — is derived, never hand-tuned per component.
    • 
          
  • A new component is "done" when it's built entirely from semantic tokens (tier 2) and contains zero literal hex values.
    • 
          
  • A new semantic token is only added when two or more components need the same color decision. One-off needs stay component-local.
    • 
          
  • Version the token set independently from the component library (semver). A palette swap is a minor bump; adding a new semantic role is a minor bump; removing one is a major bump.
    • 
        

      

    


    

      Token engine runs entirely client-side — change any seed color above and every swatch, contrast badge and component on this page recomputes instantly.
